What MAVIS can credibly claim—and what to build next

The current project supports a useful systems contribution. It does not yet establish a new continual-learning algorithm or prove beneficial memory–EWC synergy.

Recommendation: retain the shared prototype-memory architecture, and investigate whether measured retrieval utility can determine where parameter protection is needed. Treat this as a falsifiable research hypothesis. Neither an exact-title search nor combining familiar mechanisms proves originality.

1. The strongest contribution already implemented

Geometry-consistent shared prototype memory for retrieval, feature replay, and inference. This is an accurate description of the implemented design, not a verified first-in-literature claim.

MAVIS stores multiple prototypes per class and a class-level diagonal variance. The same memory supports attention retrieval during image processing, Gaussian feature replay for classifier training, and prototype-based inference. Replay vectors pass through the attention/fusion path used by live features. Direction-normalized reconstruction and variance measurement in normalized feature space address concrete failures caused by incompatible feature scales.

  • models/memory.py: K-means prototypes, normalized-space class variances, running current-task prototypes, and maximum cosine similarity across a class's prototypes. The predictor called NCM is therefore multi-prototype nearest-neighbor scoring, not strictly a single nearest class mean.
  • models/mavis.py: image-feature attention, vector-valued gated fusion, and replay-query rescaling to approximately √D before using the same fusion path.
  • continual/mavis_trainer.py: replay, normalized attention reconstruction, dual-teacher feature distillation, pooled spatial distillation, head finetuning, and task-mixture prediction.

Ready-to-use current contribution statement: “MAVIS integrates a shared multi-prototype memory across attention-based feature fusion, normalized feature replay, and prototype-assisted prediction. We evaluate its interaction with Online EWC and identify geometric consistency and historical-data access as critical conditions for interpreting retention gains.”

Use “integrates” and “evaluates.” The current evidence does not justify “first,” “optimal,” “state of the art,” “eliminates forgetting,” or “proves super-additive synergy.”

3. Findings that change the novelty claim

  1. Historical image access is extensive. After each task, train_task calls get_task_train_dataloader(past_t) and rebuilds old prototypes with the current encoder. This is training-data reuse, not test leakage, but it invalidates a strict exemplar-free or discarded-stream claim. Removing this access is a new experimental setting, not a wording change.
  2. The budget is fixed only for the configured horizon. Stored prototypes scale as classes × K × D, and memory.capacity does not implement eviction or reallocation. At 200 classes, K=10, D=512, float32 prototype vectors occupy 3.91 MiB; class variances add 0.39 MiB. These exclude running buffers, network weights, teachers, EWC state, optimizer, activations, images, and caches.
  3. EWC needs a stronger implementation baseline. compute_fisher averages squared batch-mean gradients. This differs from the mean of squared per-example gradients, includes cross-example cancellation, and depends on batch size. A negative M4 result is not evidence that EWC generally fails.
  4. Replay does not protect the encoder through replay gradients. Fusion of replay inputs runs under torch.no_grad(), so its classification loss updates the head. The encoder is constrained by live-data objectives, distillation, and EWC.
  5. Several advertised features are weaker than their names. Weight alignment resets already-unit buffers; “Gaussian covariance replay” uses a shared diagonal variance per class, not a full covariance or separate component covariance; hierarchical prediction is a heuristic mixture using a valid conditional-probability identity, not a new Bayesian learning theorem.
  6. Geometry is improved but not perfectly unified. K-means operates on raw features and normalizes final centroids; variances are measured after normalization. Replay query norms use fixed √D rather than measured current norms, and reconstruction queries have a different norm from live queries. Existing corrections should not be described as a full distribution-matching guarantee.
  7. Saved results are not completely provenance-locked. JSON records seed, width, task/epoch counts, and selected EWC settings, but not a complete immutable configuration and source commit. The 15 archive JSONs are byte-identical to the 15 main factorial JSONs: these are copies, not 15 additional experiments.

4. Closest prior work and the claim boundaries

These are primary papers inspected through their abstracts or accessible paper text. This is a targeted novelty screen, not an exhaustive systematic review or patent search.

  • Kirkpatrick et al., EWC (2017): protecting important parameters is established. The source also explicitly cites Online EWC from Progress & Compress.
  • PASS (CVPR 2021): prototype storage and augmentation in feature space already address old-class retention. Prototype replay alone is not the novelty.
  • Semantic Drift Compensation (CVPR 2020): estimates historical feature drift from current-task data without old exemplars. Replacing refresh with generic drift correction is not automatically new.
  • PODNet (ECCV 2020): pooled spatial distillation and multi-proxy representations have precedent. MAVIS uses a related spatial constraint.
  • FeTrIL (WACV 2023): creates old-class pseudo-features by translating new-class features, using a fixed extractor. It is a relevant alternative to Gaussian replay.
  • Navigating Semantic Drift / MACIL (2025): addresses mean and covariance shifts. Simply adding covariance-aware drift adaptation would have substantial overlap.
  • DiAPR (AAAI 2026): dimension-level prototype refinement for non-exemplar CIL, including Tiny ImageNet results. New prototype-adjustment proposals need comparison against this work.
  • Uncertainty-based Continual Learning with Adaptive Regularization (NeurIPS 2019) and Adaptive Memory Replay (CVPR Workshops 2024): adaptive protection and replay allocation are established areas. “Uncertainty-aware” alone is insufficient differentiation.
  • EWC Done Right (2026): investigates importance-estimation failures and proposes logit reversal. This is a relevant stronger EWC comparator; its reported performance is not directly comparable to MAVIS without matched protocols.

5. Recommended research direction: retrieval-utility-conditioned consolidation

Working title: “MAVIS: Coordinating Prototype Retrieval and Parameter Consolidation Through Measured Memory Utility.”

Proposed contribution statement: “We investigate a continual-learning controller that measures the marginal predictive benefit of prototype retrieval and uses it to allocate parameter protection, testing whether coordinated memory and consolidation outperform independently tuned mechanisms under matched data, memory, and compute budgets.”

Status: proposed, not implemented or validated. The potential contribution is the explicit measurement-to-protection coupling and its demonstrated effect. The search did not establish that this exact coupling is absent from all prior work. A method-level review of adjacent adaptive replay/regularization papers is still required before a priority claim.

A concrete first experiment

  1. Choose a truthful protocol. Use a declared, fixed total budget of stored training exemplars plus prototype statistics. Replace full historical-dataset refresh with budgeted access. Give all comparator methods the same budget and account separately for teachers/EWC state. This first version is bounded-rehearsal CIL, not exemplar-free CIL.
  2. Measure retrieval benefit with a paired intervention. On a training-only calibration subset of the retained examples, compare cross-entropy with the retrieval branch enabled and bypassed. Use the same image and model checkpoint. Define u(x) = loss_without_retrieval(x) − loss_with_retrieval(x). Positive utility means retrieval reduces loss. This is an ablation-based utility estimate, not proof of causality in an unrestricted sense.
  3. Make the intervention fair. A classifier trained exclusively on fused features may fail on raw features merely because of distribution shift. Train both routes with controlled path dropout, or use matched calibrated heads; include that change in every comparator. Use disjoint training/calibration roles where feasible, and report the extra model/compute cost. Never tune utility thresholds on test images.
  4. Condition protection on residual vulnerability. Use a bounded, slowly updated weight that is larger for examples where both fused prediction is poor and retrieval offers little help. Compute per-example squared gradients and accumulate an importance estimate weighted by this signal. Keep total importance magnitude matched to ordinary EWC to distinguish allocation from a trivial λ change. Smooth or freeze weights within a task; specify update frequency before experiments.
  5. Test the premise directly. Reliable retrieval may itself depend on parameters that need protection. Reducing their protection can backfire. Compare utility-conditioned weights against the reversed rule, shuffled weights, and uniform weights. Reject the proposed mechanism if the benefit disappears under these controls.

A possible research specification is w(x)=ε+(1−q(x))r(x), where q is a bounded calibrated utility score and r is bounded fused-prediction risk. Then Futility_i = mean_x[w(x)·(∂ log p(y|x)/∂θ_i)²], rescaled to match the total mass of the ordinary importance estimate before online accumulation. This equation is a testable design proposal, not a derived optimal rule.

Start with consolidation alone. Extending the same signal to retrieval gates, replay quotas, and inference routing should follow only if the first controlled experiment works. Changing all three immediately would make attribution difficult.

For a strict exemplar-free version, prototype-space measurements cannot directly reveal encoder forgetting because replay bypasses the image encoder. Such a version needs a separately justified drift/utility estimator and must be evaluated against SDC, FeTrIL, MACIL, and DiAPR. Do not silently assume synthetic confidence measures old-image accuracy.

6. Minimum evidence needed for a stronger claim

  1. Reproducible base: lock source revision, complete config, data split, class order, seeds, hardware and package versions. Fix or explicitly benchmark the batch-gradient importance estimator; sweep λ including zero. Reserve a tuning split.
  2. Complete the missing control: add M3 without attention. This completes attention on/off × EWC on/off within the same MAVIS trainer and shared losses. Report head, prototype, ensemble and hierarchical predictors separately.
  3. Quantify refresh dependence: compare no refresh, fixed-budget exemplar refresh, and full historical refresh. Treat the full-data variant as a privileged-access reference. Match any retained examples in replay baselines.
  4. Test geometry independently: isolate normalized replay variance, normalized reconstruction, and query-scale matching. Compare no fusion, live-only fusion, and shared live/replay fusion. Report downstream accuracy, not just replay self-classification.
  5. Test utility allocation: compare no EWC, validation-tuned EWC with corrected importance estimation, utility-conditioned EWC, shuffled/reversed utility, and equal-total-penalty controls. Hold replay, predictor, tuning budget, and access fixed.
  6. Expand evidence: use at least Tiny ImageNet and CIFAR-100, multiple class orders and training seeds; choose the final run count from pilot variance and a predeclared practical effect size. Match pretraining policy, backbone, budget and incremental schedule for published baselines.
  7. Report tradeoffs: final and average incremental accuracy, old/new accuracy, initial learning accuracy, forgetting, calibration, persistent bytes, peak training memory, wall time and extra forward/backward passes. Lower forgetting alone is not success.

Success criterion: utility-conditioned consolidation improves the accuracy–retention tradeoff over both the best no-EWC configuration and a fairly tuned ordinary-EWC configuration, across seeds/orders, without relying on extra historical data or hidden compute. If it cannot beat λ=0 or equal-penalty controls, the central algorithmic hypothesis is unsupported.

7. A defensible paper using the current implementation

Suggested title: “When Prototype Memory Helps: Geometry, Retrieval, and Consolidation in Class-Incremental Learning.”

This empirical direction is closer to the existing evidence than inventing another module. Its contribution would be a controlled study showing which memory uses help, how geometric mismatches break them, how much historical refresh contributes, and when EWC becomes redundant or harmful. Additional controlled ablations are still needed; existing bug fixes and historical logs alone are not a completed publication.
